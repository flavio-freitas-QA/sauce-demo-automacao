# Dia 007 — Refatoração da suíte (Sauce Demo)

Dia dedicado a qualidade interna: nenhum cenário novo, mas a suíte inteira ficou mais rápida, mais tipada e mais fiel ao uso real da aplicação.

## O que mudou

### 1. Login programático com cache de sessão

O Sauce Demo autentica apenas pelo cookie `session-username`. O fluxo de login pela UI continua coberto de ponta a ponta no dia 001 — mas os demais specs não precisam repeti-lo a cada teste.

- **Cypress**: novo comando `cy.login(username)` usando `cy.session()` + `cy.setCookie()`. A sessão é cacheada e restaurada entre testes.
- **Playwright**: fixture `loginAs` criada via `test.extend()` em `playwright/support/fixtures.ts`, injetando o cookie no contexto.

Antes de adotar a técnica, a hipótese foi validada com um script de sondagem: injetar o cookie e navegar direto para `/inventory.html` funciona.

Exceções que continuam usando a UI de login, de propósito:
- `dia-001` (o objeto do teste é o próprio login);
- `performance-glitch` (o objetivo é medir o fluxo real com o atraso do usuário).

### 2. Seletores padronizados em `data-test`

Um script de sondagem (Playwright) mapeou todos os atributos `data-test` expostos pelas páginas do site (inventário, detalhe, carrinho, três etapas do checkout e login). Os Page Objects passaram a usar esses atributos — `[data-test='inventory-list']`, `[data-test='shopping-cart-badge']`, `[data-test='title']`, `[data-test='subtotal-label']` etc.

Exceções documentadas nos próprios Page Objects:
- `.cart_item`: os itens do carrinho recebem `data-test="inventory-item"` (mesmo valor do catálogo), então a classe é mais expressiva ali;
- `.bm-menu-wrap`: o wrapper do menu lateral vem da lib react-burger-menu e não tem `data-test`;
- botão de ação do detalhe do produto: alterna entre `data-test='add-to-cart'` e `'remove'`, então o container é o seletor estável para ler o rótulo.

Um efeito colateral bom: os `data-test` de nome/descrição/preço são idênticos no catálogo e no detalhe do produto, unificando seletores entre telas.

### 3. Fim do `catch` global de exceções

O `Cypress.on("uncaught:exception", () => false)` global em `e2e.ts` engolia **qualquer** erro da aplicação — um TypeError legítimo passaria despercebido em todos os specs. Agora o handler é registrado com `cy.on()` (escopo de teste) apenas nos specs que exercitam usuários intencionalmente quebrados (`problem_user`, `error_user`).

### 4. Fixtures tipadas

Os specs Cypress importam os JSONs de fixture diretamente (`resolveJsonModule`), como o Playwright já fazia. Isso elimina todos os `let users: any` e o boilerplate de `cy.fixture().then()` em duplo `beforeEach` — com tipagem estática de graça: um typo em `products.backpak` agora quebra o `typecheck`.

### 5. Navegação realista para o carrinho

Os fluxos passam a clicar no ícone do carrinho (`InventoryPage.openCart()`) em vez de `cy.visit("/cart.html")`. O acesso direto por URL continua testado onde ele é o cenário: guarda de rota sem login e deep link autenticado.

Detalhe descoberto na validação: o site responde **status HTTP 404** para as subrotas do SPA (hospedagem estática), embora sirva a aplicação normalmente — por isso todo `cy.visit` de subrota precisa de `failOnStatusCode: false` (agora comentado no código; o Playwright não falha por status e não precisa disso).

### 6. Bugs conhecidos como anotações (Playwright)

Os testes `[BUG CONHECIDO]` do dia 006 agora registram `test.info().annotations` com tipo `known-bug`, visíveis no relatório HTML. No Cypress, os ramos duplicados de `error_user`/`visual_user` foram unificados (paridade com o Playwright).

### 7. Relatório HTML no Cypress

Adicionado `cypress-mochawesome-reporter` (report em `cypress/reports`, com screenshots embutidos). O CI publica o relatório como artifact, fechando a assimetria com o Playwright, que já tinha HTML + JSON.

### 8. Correções pontuais

- `InventoryPage.visit()` e `CartPage.visit()` (Cypress) visitavam `/` em vez das rotas corretas;
- `docs/day-001.md` renomeado para `dia-001.md` (padrão dos demais);
- título do teste de persistência do carrinho não afirma mais que o estado vive em `sessionStorage` (não é o mecanismo do app).
